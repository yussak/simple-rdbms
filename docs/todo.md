## 現在地

Phase 0 の途中。`CREATE TABLE` と `SELECT` は、SQL の字句解析・構文解析からメモリ上の実行までつながっている。
`INSERT` は単一行・全列の構文解析まで対応し、非負整数・文字列を区別した AST を返す。実行は未実装で、SELECT のテストデータは Go のコードで直接登録している。
`go run .` はまだ `simple-rdbms: hello` を表示するだけで、SQL を入力する CLI はない。

`CREATE TABLE` で指定した `INT` / `TEXT` は、実行器で内部の型に変換し、列定義に保存する（[ADR 0003](adr/0003-typed-values-and-columns.md)）。
行データと SELECT の結果は `value.Value` で整数・文字列を区別して保持する。テーブルはメモリ上にあり、ファイルへの永続化はまだ行わない。

INSERT の完成条件は `engine/insert_integration_test.go` に結合テストとして用意されている。INSERT の実行は未実装のため理由付きの `t.Skip` があり、動作検証はまだ完了していない。

### INSERT で追加した行を SELECT で取得できるようにする

## その後のロードマップ

実装順序の理由は [ADR 0001](adr/0001-phase-implementation-order.md) に記載する。各 Phase に着手するときに具体的なタスクへ分解する。

| Phase | 内容 | 完了の目安 |
|---|---|---|
| 1 | WHERE（フルスキャン＋フィルタ） | 条件に合う行だけ取得できる |
| 2 | ファイル永続化（ページ単位のストレージ） | 再起動後もデータが残る |
| 3 | B+木インデックス＋主キー検索 | フルスキャンとインデックス検索の結果が一致する |
| 4 | WAL＋トランザクション | 書き込み途中のクラッシュから復旧できる |
| 5 | TCP 接続（簡易な独自プロトコル） | ネットワーク経由でクエリを実行できる |
