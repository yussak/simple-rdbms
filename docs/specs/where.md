# WHERE の仕様

SELECT に WHERE を指定し、条件に一致する行だけ取得できるようにする。
この文書は WHERE の振る舞いを定めるもので、実装の構成や作業手順は扱わない。

## 対応範囲

- 比較演算子：`=`、`<>`、`<`、`<=`、`>`、`>=`
- AND / OR による複数条件の組み合わせ
- 括弧による条件のグループ化と入れ子
- 既存の INT 列と TEXT 列
- 全列取得と指定列取得

PostgreSQL を参考にするが、現時点では厳密な互換性を目指さない。
今回の簡略化と未対応の範囲は以下に明記する。

## 構文

```sql
SELECT 列指定 FROM テーブル名 WHERE 条件;
```

比較は左辺を列名、右辺をリテラル値とする。
リテラル値の表記は既存の INSERT と同じ範囲とし、非負の10進整数と単一引用符で囲んだ文字列に対応する。
整数は既存の INT と同じく符号付き64ビット整数の範囲とする。
文字列中の単一引用符は `''` と書く。

```sql
SELECT * FROM users WHERE id = 1;
SELECT name FROM users WHERE id >= 2 AND id <= 4;
SELECT * FROM users WHERE name = 'Alice' OR name = 'Bob';
SELECT * FROM users WHERE id >= 2 AND (name = 'Alice' OR name = 'Bob');
```

WHERE と文末のセミコロンはそれぞれ省略できる。
キーワードの大文字・小文字は区別しない。

## 条件の評価

- 比較演算子を AND / OR より先に評価する。
- AND を OR より先に評価する。
- 括弧は上記の優先順位より優先する。
- AND は両方の条件が真の場合、OR は少なくとも一方が真の場合に真となる。
- 条件の評価順序や短絡評価は保証しない。

たとえば、次の二つは同じ意味になる。

```sql
WHERE id = 1 OR id = 2 AND name = 'Bob'
WHERE id = 1 OR (id = 2 AND name = 'Bob')
```

## 値の比較

- INT 列は整数リテラルと数値として比較する。
- TEXT 列は文字列リテラルと比較する。
- 異なる型の比較はエラーとし、暗黙の型変換は行わない。
- 文字列の等価比較は完全一致とし、大文字・小文字を区別する。
- 文字列の大小比較は UTF-8 のバイト順とする。ロケールに応じた並べ替えや Unicode 正規化は行わない。

したがって、`id = 2` と `name = '2'` は受け付けるが、`id = '2'` と `name = 2` はエラーにする。
文字列では `'Alice'` と `'alice'` は等しくなく、`'10' < '2'` は真となる。

## 検索結果

- 条件に一致する行をすべて返す。重複する行も保持する。
- 一致する行がなければ、列情報を持つ0行の結果を返す。
- 結果に含めない列も条件に指定できる。
- WHERE を省略した場合は既存の SELECT と同じ動作とする。
- 結果の行順は保証しない。
- 検索によって保存済みのデータは変更しない。

## エラー

次の場合はエラーにする。

- 存在しないテーブルや列を指定した。
- WHERE の後に条件がない。
- 比較の左右の要素や演算子が不足している。
- 比較の型が一致しない、または整数リテラルが対応範囲を超えている。
- AND / OR の前後に条件がない。
- 括弧の対応が取れていない、または括弧の中が空である。
- 未対応の構文や文末の余分な入力がある。

不明な列や型の不一致は、テーブルが空の場合や、OR の別の条件が真となる場合でもエラーにする。
未対応の条件を読み捨てて、条件の一部だけで実行してはならない。
エラーメッセージの文面やエラーコードの PostgreSQL 互換は求めない。

## 動作例

以下のデータを使用する。

| id（INT） | name（TEXT） |
|---|---|
| 1 | Alice |
| 2 | Bob |
| 3 | Alice |
| 4 | Carol |

取得される id は、結果の行順を指定するものではない。

| WHERE の条件 | 取得される id |
|---|---|
| `id = 2` | 2 |
| `id <> 2` | 1、3、4 |
| `id > 2` | 3、4 |
| `id < 2` | 1 |
| `id >= 2 AND id <= 3` | 2、3 |
| `name = 'Alice'` | 1、3 |
| `name < 'Bob'` | 1、3 |
| `id = 1 OR id = 2 AND name = 'Bob'` | 1、2 |
| `(id = 1 OR id = 2) AND name = 'Bob'` | 2 |
| `id >= 2 AND (name = 'Alice' OR (name = 'Bob' AND id = 2))` | 2、3 |
| `id = 99` | なし |

```sql
SELECT name FROM users WHERE id = 2;
```

この場合、結果の列は `name` だけで、値は `'Bob'` となる。

## 今回は未対応とするもの

- NOT、NULL、IS NULL、IS NOT NULL
- IN、BETWEEN、LIKE
- 比較演算子 `!=`（PostgreSQL では `<>` の別表記）
- 列同士の比較、左辺がリテラルの比較、比較の連鎖
- 算術式、関数、サブクエリ
- 負数など、既存の INSERT で扱えないリテラル表記
- PostgreSQL の引用符付きリテラルの型推論と型変換、明示的なキャスト
- 照合順序の指定やロケールに応じた文字列比較

## PostgreSQL との関係・参考資料

- [比較演算子](https://www.postgresql.org/docs/18/functions-comparison.html)：今回対応する6種類の比較演算子を参考にする。`!=` は今回扱わない。
- [演算子の優先順位](https://www.postgresql.org/docs/18/sql-syntax-lexical.html#SQL-PRECEDENCE)：比較、AND、OR の優先順位を合わせる。
- [演算子の型解決](https://www.postgresql.org/docs/18/typeconv-oper.html)：PostgreSQL は引用符付きリテラルを比較相手の型に解決できるが、今回は型が一致する比較に限定する。
- [照合順序](https://www.postgresql.org/docs/18/collation.html)：今回の文字列比較は UTF-8 環境の C 照合順序に相当する規則を採用し、照合順序の切り替えは扱わない。

既存の INT は符号付き64ビット整数であり、PostgreSQL の `integer`（32ビット）とは異なる。この型の範囲は今回変更しない。
