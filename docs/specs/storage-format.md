# 永続DBの保存形式 v1

この形式は [永続化の設計](../design/persistence.md)に対応する。PostgreSQLのrelation、固定長ページ、項目識別子、システムカタログの関係を取り入れ、バイト配置はこの実装用に簡略化した。PostgreSQLのファイルとの互換性はない。

## ディレクトリと起動

`OpenDatabase(path)` の `path` はDBディレクトリである。存在しなければ新しく作り、存在すれば既存DBとして検証する。空ではない既存ディレクトリを初期化し直さない。

```text
path/
├── CONTROL
└── relations/
    ├── 1    テーブルカタログ
    ├── 2    列カタログ
    └── 3以降 ユーザーテーブル
```

CONTROLは16バイト固定。オフセット0にASCII `SRDBMS01`（8バイト）、8に形式バージョン `1`（符号なし32ビット）、12にページ長 `8192`（符号なし32ビット）を置く。整数はすべてリトルエンディアン。長さ・識別子・バージョンが一致しなければ開かない。

relation番号1と2の列定義は、起動のためにコード内で固定する。両カタログもユーザーテーブルと同じページと行の形式で保存する。

| relation | 列の順序 |
| --- | --- |
| 1 テーブルカタログ | relation ID: INT、テーブル名: TEXT、行ファイル番号: INT |
| 2 列カタログ | relation ID: INT、列番号: INT（1始まり）、列名: TEXT、内部型: INT |

初版ではrelation IDと行ファイル番号を同じ値にする。新しい番号はカタログ内の最大値から決める。起動時は両カタログから名前・列定義・ファイル番号を復元し、ユーザーテーブルの行は読み込まない。

## ページ

relationファイルは8192バイトのページを連結する。空のrelationファイルは0バイト。行はページ境界をまたがない。

| オフセット | 長さ | 内容 |
| --- | ---: | --- |
| 0 | 4 | ASCII `PAG1` |
| 4 | 2 | `lower`: ヘッダーと項目識別子の末尾 |
| 6 | 2 | `upper`: 行本体領域の先頭 |
| 8以降 | 1件4 | 項目識別子: 行オフセット2バイト、行長2バイト |
| `lower` から `upper` | 可変 | 空き領域 |
| `upper` から8192 | 可変 | 行本体 |

新規ページは `lower=8`、`upper=8192`。項目識別子は前から、行本体は後ろから追加する。項目識別子の順番がINSERT順であり、SELECTはファイル先頭のページから順に各項目識別子を読む。末尾ページに `行長 + 4` バイトの空きがなければ、新しいページを末尾に追加する。1行の最大長は `8192 - 8 - 4 = 8180` バイト。

ページを読むときは、識別子、境界、項目識別子の長さと位置を検証する。relationファイル長はページ長の倍数でなければならない。

## 行

行に型タグや列名は置かず、カタログから復元した列定義の順に値を読む。NULL、可変長行のページまたぎ、行の削除印はまだ扱わない。

| 型 | 保存形式 |
| --- | --- |
| INT | 符号付き64ビット整数を8バイト。リトルエンディアン |
| TEXT | UTF-8バイト長を符号なし32ビット整数で4バイト、続けてその長さの文字列 |

列数と型、UTF-8、行長をファイル更新前に検証する。読んだ行が途中で終わる場合、余分なバイトがある場合はエラーにする。初版は8180バイトを超える行を拒否する。PostgreSQLのTOASTに相当する長い値の退避は後で検討する。

## 書き込みと保証

CREATEでは行ファイルを作り、テーブルカタログに1行、列カタログに列数分の行を追加する。INSERTでは対象のrelation末尾ページに行を追加する。各ファイル更新後に同期し、CREATE時のファイル作成ではディレクトリも同期する。SELECTは対象relationをページ順に読み、既存のWHERE判定と列選択に渡す。`Close` に書き込みをためない。

入力検証に失敗した場合は保存内容を変えない。複数ファイルの更新途中にI/Oエラーやクラッシュが起きた場合の原子性・復旧は保証しない。WALを実装する段階で扱う。永続DBでのDELETEは現時点でエラーにする。

参考: [PostgreSQLのページ構成](https://www.postgresql.org/docs/current/storage-page-layout.html)、[ファイル構成](https://www.postgresql.org/docs/current/storage-file-layout.html)、[システムカタログ](https://www.postgresql.org/docs/current/catalogs.html)。
